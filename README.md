<details>
<summary><b>📐 Template for each individual project repo (reproducibility checklist)</b></summary>

Each featured project's own repo should follow a consistent structure so others can run it:

```text
project-name/
├── README.md              # Problem, data, approach, results, how to run
├── environment.yml        # or requirements.txt / pyproject.toml
├── data/
│   ├── raw/               # Never edited by hand (or document how to download)
│   └── processed/
├── notebooks/             # Numbered: 01_eda.ipynb, 02_modeling.ipynb
├── src/                   # Reusable code: features, training, evaluation
├── tests/
├── models/                # Or link to model registry / release
├── reports/figures/
└── LICENSE
```

**Project README checklist**
- [ ] One-paragraph summary with the headline result
- [ ] Data source, license, and how to obtain it
- [ ] Setup instructions that actually work (`pip install -r requirements.txt`)
- [ ] How to reproduce the main results (one command if possible)
- [ ] Evaluation metrics and baseline comparison
- [ ] Limitations and next steps (honesty builds trust)
- [ ] Random seeds fixed / environment pinned
